# 粗剪实际画面抽检与改版对照 · #13

日期：2026-11-09。任务：[GitHub #13](https://github.com/Moosphan/MyDashboard/issues/13)，父任务 #10，兄弟任务 #11/#12；#14 负责完整横竖版影片验收。本页不代表整片视觉质量已获批准。

## 已确认入口与行为

用户确认在粗剪播放器规格行增加“实际画面抽检”按钮，打开既有 WorkflowDialog。选分镜后从该粗剪 MP4 提取前段 20%、中段 50%、后段 80% 的最近有效帧，显示版本、创建时间、视频指纹、时间、帧号及实测帧率。可以分页选择更早粗剪，按共同稳定分镜 ID 和各自冻结配音时长并排比较；时间轴变长或缩短不使用同一绝对秒数误比。

点击预览版本抽检帧会关闭弹窗、暂停并定位主播放器。旧版帧仅供查看。反馈跳转到原修改计划入口，继续人工确认、合成和审核；历史预览不新增修改入口。技术检查记录与人工审核状态分别显示，不把抽帧成功或渲染成功视为视觉通过。

## 数据与失败边界

- 仅使用所选版本明确记录的 sourceStoryboard/sourceAudio，不回退到最新分镜或配音；未记录或缺失时说明无法逐镜抽检，可以直接观看原视频。
- 来源时间轴需完整且稳定 ID 不重复；没有相同分镜时明确无法对照，不借用另一镜。
- FFprobe 检查实际固定帧率和视频时长；不支持可靠定位的可变帧率或时长冲突时明确失败。抽帧 JPEG 最长边 640px，只用于检查，原视频不改动。
- 每次抽帧先校验项目归属、源视频文件指纹；命中本次应用会话缓存仍复验源视频及图片，缓存图片损坏可重新抽取。
- 抽检派生图片登记为受管文件，但不新增阶段版本、执行任务、审核或修改计划。关闭/换镜/换版取消旧请求并忽略迟到响应；退出应用终止正在进行的抽帧。
- 每请求最多三帧、总时限 60 秒，单次工具执行 20 秒；共享现有媒体进程预算。会话缓存最多 128 组，重启应用后需要重新抽取。
- 没有调用 Agent，也没有引入视觉模板、动作枚举或限制原生源码创作。

## 验收限制

自动化 UI 使用合成影片，验证交互与真实抽帧链路；它不能证明创意、字幕遮挡或所有镜头的观感已合格。短镜头可能多个采样阶段落在同一有效帧，时间和帧号如实显示。没有共同稳定 ID 或完整来源的历史版本无法按镜自动对照。完整影片仍需 #14 的实际横竖版产出、完整播放与人工验收。
